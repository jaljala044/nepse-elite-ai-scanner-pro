## 1. Runtime identity gate

Hardened `backend/app/temporal_registry.py`:

- `SecurityMasterRecord` now carries an explicit evidence tier, stable-ID verification flag and effective-date verification flag.
- `security_as_of` resolves only when both stable ID and effective date are verified using primary NEPSE or CDSC evidence.
- Current-snapshot-only IDs, secondary first-trade/archive dates and primary notices without a proven stable ID return `unverified_identity`; they cannot resolve a historical security join.
- Conflicting overlapping identities remain `ambiguous` and fail closed.
- Security-master validation reports verified versus unverified identity coverage.

The versioned feature store now propagates the identity gate. An unverified or ambiguous security does not join corporate actions.

## 2. Corporate-action gate

Hardened both the temporal registry and `backend/app/corporate_action_policy.py`:

- Corporate-action context is filtered by `available_at` against the decision timestamp; later announcements are excluded from earlier snapshots.
- Secondary-verified actions may appear as context, but cannot authorize price adjustment.
- Adjustment eligibility requires a confirmed action, a primary NEPSE/CDSC source, a present factor, and independent review.
- Unverified actions known by the decision time are excluded and mark the action context incomplete.
- The feature store exposes adjustment-eligible actions separately from context actions and explicitly reports that corporate-action source-universe completeness is **not verified**.
- No raw OHLCV series is mutated; adjustment remains a separate review gate.
