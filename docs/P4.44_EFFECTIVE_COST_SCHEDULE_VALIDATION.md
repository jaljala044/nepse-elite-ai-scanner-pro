# P4.44 effective-dated cost schedule validation

**Status:** implementation committed; CI execution pending; review-only.

## Rechecked project state

- The master main branch contains the explicit flat-rate scenario calculator backend/app/execution_costs.py and six baseline tests.
- The older p4-44-nepse-realistic-execution-cost-backtest branch is 107 commits ahead and 191 behind main; it contains an execution simulator but is not safe to merge wholesale. Its execution model requires caller-supplied price bands, calendar evidence, liquidity thresholds and cost assumptions, and does not certify official schedules or fills.
- Current main does not contain the execution simulator files from that divergent branch.
- Open product issue #85/#86 permits deterministic portfolio work in parallel but requires private per-user isolation and does not permit unverified market data in recommendations.
- No official, dated brokerage/tax schedule evidence was authenticated in this work.

## Implemented in this PR

- backend/app/effective_cost_schedule.py resolves caller-supplied brokerage slabs by transaction date, amount and buy/sell side.
- Tax schedules are selected by inclusive effective-date interval.
- Missing, overlapping or provenance-incomplete schedules fail closed.
- Source schedule ID, source ID and SHA-256 are retained in the resolved scenario assumptions.
- backend/tests/test_effective_cost_schedule.py adds ten tests for slab boundaries, independent buy/sell slab selection, inclusive effective dates, missing tax coverage, tax gaps, overlapping periods, brokerage slab gaps/overlaps, source hash requirements, DP/minimum brokerage and integration with the existing round-trip calculator.
- Outputs remain production_eligible=false; supplied schedules are not automatically treated as official.
