# P4.34 — Validated Broker Memory Promotion

## Purpose
Connect the P4.33 ingestion report to the P4.32 persistent DuckDB memory store without weakening the fail-closed admission boundary.

## Promotion contract
- Rejects any report that is not memory-eligible: coverage COMPLETE, accepted rows non-empty, and quarantine empty.
- Revalidates descriptive-only status and timezone-aware availability; upstream ingestion must supply verified session-finality timestamps before a row can be accepted.
- Adapts P4.33 broker/session provenance into P4.31's verified observation contract.
- Builds daily/weekly/monthly/yearly descriptive windows.
- A window is persisted only when the full requested number of distinct observed dates is present (1/5/21/252). Incomplete windows are withheld and reported.
- Retains source IDs, evidence IDs, payload hashes, batch ID, coverage and methodology version.
- Uses deterministic batch/as-of idempotency keys and atomic batch append. Exact replay is a no-op; conflicting replay rejects the whole append.

## Interpretation boundary
Stored net buy/sell is descriptive broker-side activity only. It is not proof of beneficial ownership, accumulation, distribution, operator intent or a BUY/SELL signal. Sparse windows are withheld. No absent broker/security/date observation is synthesized as zero.

## Scope limitations
P4.34 does not fetch source data, authenticate source publishers, independently certify broker identity, or establish exchange session calendars. P4.33 callers must supply those verified registries and a complete source inventory. The memory store remains append-only through its application interface; privileged direct database-file access is outside this guarantee.

## Tests
backend/tests/test_broker_memory_promotion.py covers fail-closed rejection, complete-window gating, replay idempotency, evidence lineage, descriptive status, and point-in-time availability.
