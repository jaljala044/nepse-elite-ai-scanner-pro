# P4.36 — Secure Floorsheet Source Capture

## Purpose

Provide the transport/capture layer missing between an approved public floorsheet
endpoint and the P4.35 normalized floorsheet adapter. This component fetches and
preserves exact response bytes. It does not parse the provider schema or infer
exchange sessions.

## Endpoint policy

A caller must supply a reviewed `FloorsheetCapturePolicy` containing:
- Stable source ID.
- Exact allowlisted HTTPS hostname.
- Allowlisted absolute path prefix.
- Maximum response size.
- Allowed response media types.
- Rights review status and parser version.

The implementation rejects HTTP, unlisted hosts, nonstandard HTTPS ports,
credentials, query strings, fragments, paths outside the allowlist and redirects.
TLS certificate verification remains enabled. Redirects are rejected rather than
followed so an approved host cannot redirect capture to an unapproved host.

## Capture and persistence

- GET request with a narrow Accept header and a non-secret fixed User-Agent.
- Bounded response read; declared and actual body sizes are checked.
- Only HTTP 200 and non-empty allowlisted JSON/CSV media types are accepted.
- Exact response bytes are SHA-256 hashed.
- Requested and received timestamps are captured in UTC.
- Request metadata excludes authorization headers and secrets.
- The immutable payload and capture manifest are stored through the evidence
  store's bronze persistence API.
- Capture is recorded with the configured rights status, but no source trust,
  session finality, parsing, canonical verification or promotion is inferred.
- Empty normalized record list is intentional: provider schema parsing is a
  separate versioned stage once actual captured payloads have been reviewed.

## Important limitations

This is a policy-bound generic public HTTPS transport, not a live NEPSE,
ShareSansar, Chukul or NepseAlpha endpoint configuration. No provider URL,
authentication flow, endpoint contract or legal data right is assumed. A real
provider policy must be independently reviewed and configured by deployment.
No API key or credential support is included. Query-string endpoints are
intentionally rejected to avoid accidental secret capture.

A successful capture means only that bytes were retrieved from an allowlisted
host over verified HTTPS and immutably recorded. It does not authenticate the
publisher's underlying data, prove completeness, validate broker identity,
prove exchange finality, or authorize use in canonical prices, broker memory or
scanner decisions. `canonical_eligible=false` and `production_eligible=false`
remain enforced.

## Tests

`backend/tests/test_floorsheet_source_capture.py` covers exact capture,
manifest/payload hashing, catalog registration, idempotent replay, host/path
allowlists, HTTPS-only, redirect rejection, non-200 status, content type,
empty body, size limits and invalid policy configuration.
