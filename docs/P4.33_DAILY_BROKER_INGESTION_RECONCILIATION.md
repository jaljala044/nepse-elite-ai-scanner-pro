# P4.33 — Daily Broker Ingestion & Reconciliation

## Status
Implementation submitted as a fail-closed ingestion/reconciliation foundation. This is not a live source connector and does not establish that daily broker records are currently fetched from NEPSE, ShareSansar, Chukul, NepseAlpha or another provider.

## Pipeline contract
1. Caller supplies source extracts, source inventory, verified broker identities, and an independently verified exchange-session set and timezone-aware session-finality timestamps.
2. Each row is checked for nonblank identity/provenance, source membership in both the expected and received verified inventory, date/session validity, verified session-finality availability, broker identity, BUY/SELL side, finite non-negative Decimal quantities/amounts, timezone-aware availability, and SHA-256 payload integrity.
3. Natural-key duplicates with the same payload digest are skipped. A duplicate key with a different digest is quarantined.
4. If contract totals are supplied, quantity and amount are reconciled by security, broker, session and side. Mismatches block the batch.
5. Coverage is measured against the supplied expected source inventory. Missing inventory or an empty received-source set yields UNKNOWN, not zero flow. Coverage below 95% is PARTIAL. The configured threshold must be finite and within (0, 1].
6. Any quarantine, PARTIAL/UNKNOWN coverage, or failed contract reconciliation blocks all promotion from that batch.

## Safety and limits
- Only descriptive_only observations can be emitted. This module makes no claim about ownership, intent, accumulation, distribution, manipulation, or trade direction.
- Session validity and finality depend on the caller's verified exchange calendar. Rows without a timezone-aware finality timestamp are quarantined; availability before finality is rejected. No session is inferred from weekdays.
- Exact replay is idempotently skipped; conflicting replay is quarantined.
- Hash integrity checks the supplied payload against its digest; it does not independently authenticate the source publisher.
- No automatic call to BrokerMemoryStore is made. An orchestration layer must append only when memory_eligible is true and preserve evidence/source lineage.
- This does not prove provider broker mappings or completeness beyond the supplied source inventory.

## Tests
backend/tests/test_broker_ingestion.py covers valid promotion, broker/session failure, timezone and point-in-time controls, payload tampering, invalid quantities, duplicate/replay handling, contract mismatch, and partial/unknown coverage.
