# P4.31 — Broker Behaviour Memory Foundation

Status: implementation foundation; not production persistence or a trading signal.

## Scope delivered
- Deterministic broker/security descriptors over daily, weekly, monthly and yearly windows (1/5/21/252 verified observed sessions).
- Strict as-of cutoff using both event date and earliest availability date.
- Fail-closed admission for unresolved broker identity, unverified sessions, low coverage (<95%), invalid provenance and malformed values.
- Exact Decimal buy/sell/net amount and quantity totals, with evidence IDs, source IDs and immutable payload hashes retained.
- Explicit exclusions; missing rows are not synthesized as zero.
- JSON Schema contract for the memory row.

## Interpretation boundary
Net broker flow is descriptive only. It does not establish beneficial ownership, accumulation, distribution, coordination, manipulation or intent. Candidate early-entry/exit hypotheses require separate price/volume structure, persistence, market/sector context, independent evidence and calibrated walk-forward validation. This foundation does not generate BUY/SELL actions.

## Remaining before operational use
1. Durable append-only storage and idempotent keys.
2. Daily ingestion job with source/session completeness controls.
3. Effective-dated broker identity and security mappings.
4. API and web/mobile evidence cards.
5. Multi-dimensional candidate rules and disconfirming evidence.
6. Time-travel, replay, concurrency and recovery tests.
7. Historical walk-forward validation and monitoring.
8. Preserve all existing P1/P2 data admission and production-readiness gates.
