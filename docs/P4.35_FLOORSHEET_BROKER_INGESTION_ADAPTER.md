# P4.35 — Floorsheet-to-Broker Ingestion Adapter

## Purpose
Connect the existing normalized floorsheet and effective-dated broker identity pipeline to P4.33 ingestion, so only validated broker party aggregates can enter P4.34 memory promotion.

## Required upstream evidence
- Parsed normalized floorsheet contracts with exact source payload hash and physical row number.
- Buy/sell party rows from the effective-dated broker identity join.
- Independent source control totals by source/date.
- Effective-dated verified symbol-to-security-ID registry.
- Verified exchange session dates and timezone-aware session-finality timestamps.
- Expected and received source inventory plus capture availability timestamp.

## Admission sequence
1. Validate one buy and one sell party row per unique source/date/contract.
2. Run the existing exact Decimal broker party aggregator and source-control reconciler.
3. Measure broker identity coverage independently by party count, amount and quantity for every date/security/side. Unresolved broker codes remain in the denominator.
4. Require the identity coverage threshold (default 95%) for all three metrics.
5. Resolve each symbol to exactly one effective-dated verified security ID. Ambiguous, absent or out-of-range mappings block the whole batch.
6. Aggregate only verified broker entities by source/date/security/broker/side. Generate deterministic derived evidence IDs and retain original contract row/hash lineage in the derived payload.
7. Pass the aggregates to P4.33, which enforces source inventory, broker registry, verified sessions, finality, hash, availability and duplicate controls.
8. Any source-control, identity-coverage or security-mapping failure clears all accepted rows and blocks P4.34 promotion.

## Safety boundary
- Unmapped/ambiguous broker codes are never assigned canonical broker IDs.
- Current symbol mappings are not applied retroactively; effective dates are mandatory.
- Gross source controls count each contract once, only when buyer/seller observations agree.
- This adapter does not fetch provider data, authenticate a publisher, or create missing session/broker mappings.
- Outputs remain descriptive only and are not evidence of ownership, accumulation, distribution, operator intent or trade signals.

## Tests
backend/tests/test_floorsheet_broker_ingestion_adapter.py covers verified pairs, unresolved identity denominator, 95% threshold, source controls, effective-dated security mapping, session finality, source inventory and malformed party pairs.
