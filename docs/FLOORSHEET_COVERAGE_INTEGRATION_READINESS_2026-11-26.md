## Classifier admission rules

The existing `build_floorsheet_coverage_manifest` remains the sole authority for the three-state date × symbol classification:

- `TRADED`: requires a positive validated contract observation **and** verified open-session evidence, complete daily capture with reconciled controls, and verified active instrument lifecycle.
- `NO_TRADE`: requires all of the same session, daily-capture, control and lifecycle gates, with no validated contract observation.
- `UNKNOWN`: mandatory whenever any of those conditions is missing or ambiguous.

For the reviewed 2026-11-24 pair, the available evidence does not independently establish the full source acquisition chain, canonical trade date, and accepted daily control/capture status. Therefore neither the SocrateAI nor Samir file should be stamped `complete_verified` or `reconciled` for classifier admission. Their transaction rows remain review evidence, not verified observations for the canonical coverage matrix.

## Why a full 281-equity report is not yet valid

1. The exact point-in-time 281-equity instrument universe and effective-dated lifecycle is not fully verified.
2. A primary exchange-open-session calendar is not yet available for every candidate date.
3. Archive filename dates do not prove that every expected open session is represented.
4. Same-day cross-source agreement does not prove independent source lineage or exchange-origin completeness.
5. A daily total match on one date is a valuable reconciliation check, but it is not a general completeness certificate.
6. Current broker directory matches do not establish historical broker identities.

## Safe next implementation sequence

1. Acquire pinned daily raw bytes only after the data-use/rights gate is resolved; preserve source commit, path, Git blob SHA-1, byte count, SHA-256 and acquisition timestamp.
2. Parse each source with its explicit source profile. Keep source date and trade date as separate fields when their semantics differ.
3. Validate every contract row, contract-ID uniqueness, date prefix/field agreement, symbol identity, broker-code syntax, quantity/rate/amount arithmetic and duplicate/conflicting contract IDs.
4. Reconcile daily contract count, quantity and turnover against an independently captured, date-matched control source. Keep all exceptions.
5. Join only to independently verified open sessions and effective-dated instrument IDs. Do not map retired aliases or successor tickers across historical boundaries.
6. Generate an evidence ledger and review-only date × security manifest. Unknown is the default for incomplete days and unresolved lifecycle.
7. Add a source-specific adapter and tests only after a reproducible raw sample and its schema are present in the repository. Do not create fixture evidence that impersonates exchange validation.
