## Lifecycle
1. Freeze a signal with symbol, decision timestamp, horizon, action, methodology version, evidence IDs/availability timestamps and immutable plan details.
2. Canonical JSON + SHA-256 generates a stable signal ID. Evidence available after the decision timestamp is rejected.
3. Append the frozen record to DuckDB. Exact retries are idempotent; changed content under the same ID is rejected.
4. Evaluate the frozen BUY research plan against later daily OHLCV and a verified session calendar.
5. Append immutable outcome snapshots. Outcomes must link to an existing signal and matching horizon and cannot predate its decision.
6. Performance endpoint selects the latest evaluation snapshot per signal/horizon before computing entry rate, stop rate, T1-T3 touch rates, gross reference win rate, average win/loss and profit factor.

## API
- `POST /v1/research/signals` — freeze and store a signal record.
- `GET /v1/research/signals` — list immutable signals, optionally by symbol/horizon.
- `POST /v1/research/signals/{signal_id}/evaluate` — evaluate price references using server-held OHLCV and reviewed evidence plus caller-attested calendar.
- `GET /v1/research/signals/{signal_id}/outcomes` — read append-only outcomes.
- `GET /v1/research/performance` — descriptive gross reference statistics by horizon.

## Outcome rules
- Horizons use maximum observation windows: T+2 research window 5 sessions, swing 20, positional 126, investment 504. Investment can be tracked even though P4.41 does not yet generate investment entries.
- No future session is skipped when its OHLCV bar is missing; evaluation is withheld as incomplete.
- Each evaluated OHLCV row must pass the server's reviewed source, identity, lifecycle, session, price-basis, corporate-action and availability checks.
- Entry, stop and target values are price-reference touches, not fills.
- If stop and target are both touched in the same daily candle, the evaluator resolves the ambiguous sequence conservatively as stop-first and records the ambiguous session.
- Stop gaps use the opening price when it is worse than the stop reference.
- Evaluation snapshots are append-only and idempotent for identical signal/time/outcome payloads.

## Safety and limitations
- BUY/SELL/HOLD labels can be frozen only as `research_only_not_execution`; no order is routed and no fill is asserted.
- Calendar verification is a caller-supplied attestation; the endpoint checks its status, source ID, coverage and availability timestamp but does not independently fetch the exchange calendar.
- OHLCV price references are not actual execution outcomes. Fees, slippage, market impact, partial fills, circuit-limit queue priority and settlement constraints are not simulated.
- Performance summaries use the latest snapshot per signal/horizon and report gross reference returns only. They are not a backtest or evidence of strategy edge.
- Repeated evaluation snapshots remain in the audit ledger; latest-snapshot aggregation prevents repeated observations from inflating the summary sample.
- No probabilities, win-rate claims or calibrated expectancy are emitted without a larger independently validated walk-forward evaluation.
- Data not available or not verified remains unavailable; no missing row is zero-filled.
